# What FragmentedFox changes

Everything here is a default or a name change on top of Mozilla's ESR source. Prefs can still be changed by the user in `about:config` (desktop).

## Desktop

Defaults changed in `browser/app/profile/firefox.js` and `modules/libpref/init/all.js`:

- Data reporting: `datareporting.policy.dataSubmissionEnabled`, `datareporting.healthreport.uploadEnabled`, `datareporting.usage.uploadEnabled`.
- Telemetry pings: archive, shutdown, first shutdown, new profile and BHR pings, SERP categorization, Firefox account pings, and the newtab private ping.
- Crash report sending from tabs: `browser.tabs.crashReporting.sendReport`.
- Studies: `app.normandy.enabled`, `app.shield.optoutstudies.enabled`, `nimbus.rollouts.enabled`, `messaging-system.askForFeedback`, `browser.discovery.enabled`.
- Promos: `browser.vpn_promo.enabled`, `browser.promo.pin.enabled`, `browser.promo.focus.enabled`, `browser.topsites.contile.enabled`.
- Background connections: `network.captive-portal-service.enabled`, `network.connectivity-service.enabled`, `network.prefetch-next`, `browser.safebrowsing.downloads.remote.enabled`.
- HTTPS-Only mode is on (`dom.security.https_only_mode`), and encrypted DNS is on in fallback mode (`network.trr.mode` 2) with Quad9 (`https://dns.quad9.net/dns-query`) as the resolver. If Quad9 is unreachable, DNS falls back to the system resolver.
- WebRTC is off (`media.peerconnection.enabled`), so websites cannot use video calls, voice calls or peer-to-peer connections. Camera capture is also off (`media.navigator.video.enabled`) and, if WebRTC is switched back on, local network addresses stay hidden (`media.peerconnection.ice.default_address_only` and `ice.no_host`). The same four prefs are set for Android in `mobile/android/app/geckoview-prefs.js`. The CI builds also leave WebRTC out of the compile with `--disable-webrtc`. With that flag the engine compile finished (about 87 minutes), and GeckoView's `VideoCaptureTest.kt`, which needs the WebRTC classes, was deleted because it stopped the build.
- New tab page (`browser/extensions/newtab/lib/ActivityStream.sys.mjs`): sponsored content, sponsored top sites, top stories, weather and telemetry are off.

Not changed: Safe Browsing local list updates, search suggestions, and the add-on blocklist and certificate data that arrive through Remote Settings.

## Android

- `mobile/android/fenix/app/build.gradle`: application ID `com.fragmentedvisions.fragmentedfox`, `TELEMETRY` and `CRASH_REPORTING` build flags off, Mozilla's shared user ID removed from the release build type, and a signing config that reads the release key from the environment.
- `Settings.kt`: the telemetry and Contile settings default to off.
- `GleanHelper.kt` and `OnboardingFragment.kt`: Glean only uploads when the build has `TELEMETRY` on, whatever the Settings switch says, and the first-run "onboarding opt-out" ping (which is sent even when telemetry is off) is only sent in those builds. Before this change the opt-out ping went to Mozilla when the terms card was accepted on a fresh install. `check-fork.py` checks both.
- `SearchMiddleware.kt` (android-components): DuckDuckGo (`ddg`) is the default search engine whenever it is in the list for the user's region, instead of the region's default (Google in most places). A search engine the user picks still wins. `check-fork.py` checks this.
- `nimbus.fml.yaml`: the expanded toolbar (bottom navigation bar) is the default layout for new installs on phone-sized screens (`default-expanded-toolbar`). Phones that already saved a layout keep it.
- `Settings.kt`: HTTPS-Only mode defaults to on for all tabs, and encrypted DNS defaults to Increased protection (fallback to normal DNS) with Quad9 as the provider. The settings screen shows Quad9 as a custom provider.
- `ContentRecommendationsFeatureHelper.kt`: no supported locales, so Pocket recommendations and sponsored stories are disabled.
- `DefaultExtensionsPrompt.kt`, `HomeFragment.kt`: the first time the home screen is shown, a dialog offers to install uBlock Origin and Privacy Badger from Mozilla's add-ons site (`addons.mozilla.org/firefox/downloads/latest/ublock-origin` and `privacy-badger17`). Nothing is installed unless the user taps Install both, and both are allowed in private tabs. The dialog shows once (`hasSeenDefaultExtensionsPrompt` in `Settings.kt`). Not tested on a device. If either extension is not available for Android, its install fails and is logged.
- `build.gradle`: only the languages in `fragmentedfox.locales` (default `en`) are packaged and offered in the language list. Override with `-Pfragmentedfox.locales=en,de`.
- `nimbus.fml.yaml`: the marketing onboarding card (sharing install data with Mozilla's marketing partners) defaults to off.
- `onboarding.fml.yaml` and `strings.xml`: the first-run Terms of Use card shows the Mozilla Public License and README links and a FragmentedFox privacy line instead of Mozilla's Terms of Use and data-sharing text.
- `static_strings.xml`: the fixed `firefox` and `app_name_firefox` text resources, which about 30 screens use as the browser's name (trackers panel, About, setup checklist, translation dialogs, link sharing, crash screen and others), now say FragmentedFox.
- `strings.xml` (default language only): strings that refer to this browser say FragmentedFox, and the About text says it is a fork built from Mozilla's source. Strings about Mozilla services (Sync, studies, crash reports, Terms of Use) and all other languages are unchanged.

## Removed from the Android app

Removing a feature means deleting its code, resources, metrics, tests and dependencies. All the removals below are in `Stable-Main`. They were built (Android build run 23, commit `08afc0a2e5`) and installed on a phone.

- **Mozilla VPN (IP Protection):** the settings entry, menu item, toolbar pill, trust panel section, first-run prompt, snackbars, account sign-in hooks, navigation destinations, the `ip-protection` Nimbus feature, the Fenix dependency on `feature-ipprotection`, the strings in every language, the `vpn` Glean metrics and the matching tests. Left in place: the shared android-components and GeckoView VPN code, which nothing in the app uses, and entries for the deleted files in the lint and detekt baselines. `browser.ipProtection.enabled` is also false in `geckoview-prefs.js`.
- **Third-party SDKs:** Adjust marketing attribution, the Google Play install referrer and advertising ID reader (and the Return to AMO handler that used the referrer), Firebase push (so web push and push-based Send Tab alerts are gone, and were already off without a Firebase config), Google Play Integrity, and Sentry crash reporting. Their dependencies, manifest entries, build tokens, debug screens, settings, Glean metrics, the `adjust-attribution` ping and tests are removed.
- **Page summarizer ("shake to summarize"):** the summarize screen and page content extraction, the Summarize menu item and toolbar highlight, the shake detector, the Page summaries settings screen and its AI controls entry, the `shake-to-summarize` Nimbus feature, the metrics, the instrumented tests, and the `feature-summarize`, `lib-llm-mlpa` and `lib-shake` dependencies. It sent page text to a Mozilla-hosted service, so no page text leaves the device for summarising any more.
- **Installed apps probe and partner distribution code:** the startup check that listed which Mozilla apps were installed (it only fed two telemetry metrics), and the distribution manager that detected partner preinstalls (Vivo, Digital Turbine, Aura, Xiaomi). The distribution code queried other apps' content providers on first run, could switch marketing telemetry on without a prompt on partner devices, and needed the `com.adjust.preinstall.READ_PERMISSION` permission, which is gone too. Their metrics, debug screen, setting and tests are removed.
- **Growth tracking and attribution leftovers:** the conversion event system that reported install and usage milestones to Adjust (the event types, the metrics storage and its 14 settings, the one-week worker and the controller track path), the install referrer UTM settings and their fields in the Nimbus targeting context, the Meta, TikTok, Reddit and X attribution flags, and the Play Store attribution ping with its Meta metrics. They were only written by code that is gone, so they were always empty.
- **Marketing data consent:** the first-run onboarding card and its Nimbus config, the "Marketing data" switch in Data choices, the marketing telemetry settings and the marketing service type, with their metrics, strings and images. It was already unreachable. The notification channel named "Marketing" (used by in-app messages) is a different thing and stays.
- **Font list worker:** a background job that read every font on the device to build a `font-list` telemetry ping, with its font file parser, setting, ping definition and tests. Telemetry is off so nothing was uploaded, but the job still ran and read the device's font list.
- **App icon picker:** kept, as Mozilla ships it (Settings, Customize, App icon). It was removed once and put back. Its eight featured icons used Mozilla's Firefox logo variants and one outside artist's work, so they are replaced with FragmentedFox fox variations drawn by `python3 .github/scripts/make-android-icons.py`. Visible names changed: Retro 2004 is Terminal, Cuddling is Duo, Flaming is Ember, Momo is Ghost (the artist credit is gone) and Cool is Neon. Pixelated, Pride and Minimal keep their names. Internal names are unchanged on purpose (`AppRetro2004`, `AppCuddling`, `AppFlaming`, `AppMomo`, `AppCool`, the `ic_*` and `ic_launcher_*` files and the string names), so ESR merges stay small. The picker's usage metrics are in `metrics.yaml` again; they are not sent because telemetry upload is off. The solid colour and gradient icons use the FragmentedFox fox as before. Mozilla's Nimbus experiment that could change the launcher icon remotely (`alternative-app-launcher-icon` and its hook in `HomeActivity.onStop`) stays removed, so no server can change the icon; `ChangeAppLauncherIcon.kt` stays because the picker uses it.
- **Do not remove the launcher aliases from the manifest.** Builds without the 23 alternative `activity-alias` entries would not install on the maintainer's phone (Android reported "There's a problem with the app file", also on a clean install and from another app), while the same build with the aliases put back installed fine. The APK inspection found no difference except the missing alias icon files, so the cause is not understood. The picker uses the aliases again, but if the picker is ever dropped, keep them anyway until this is tested further. The fork guard fails if they are gone.
- **About screen links:** What's new, Support, Privacy notice and Know your rights pointed at Mozilla's release notes, support site and privacy notice. They now open pages in this repository: `changes.md`, the issue tracker, `PRIVACY.md` and `licensing.md` (constants in `SupportUtils.kt`, resolved against the default branch). The links work once those files are on `Stable-Main`. The guard fails if the old references come back. The first-run terms card already pointed at the licence and the README.
- **Fragmented Visions colours (Android):** the app uses the Fragmented Visions palette: void black base (#000000), charcoal surfaces (#0E0E0E and #151515), dim grey lines (#2B2B2B), soft white text (#F5F5F5), ash grey secondary text (#A6A6A6), Signal red (#D4122A), Bright red (#FF4757), Terminal green (#00FF88) and Ghost lavender (#9E8FB2). Dark is the default theme for new installs (`customization_preferences.xml`). Light is kept, recoloured with Signal red on soft white. Private mode uses Ghost lavender in place of red. Blue is not used for accents; Mozilla's information colour is lavender, and the warning colour is Bright red because the palette has no amber. In dark mode the main button is Bright red with black text, because Signal red on black is only 3.9:1 for small text (Bright red is 6.3:1); Signal red is used for selected and container surfaces and for the light theme's buttons. `python3 .github/scripts/make-android-colors.py` applies it and can be run again: it re-hues Mozilla's violet, desaturated violet and grey scales (red, lavender and neutral, keeping Mozilla's lightness steps), adds the palette as `FragmentedFoxColors.kt` and `fragmentedfox_colors.xml`, points the dark, light and private colour tokens and the Compose schemes at it, and fixes the hard-coded blue and purple colours on the home page and protections screens. android-components modules that do not depend on the colours module get the hex value instead of a reference (the guard checks this). It prints the contrast of every text pair and exits with an error below 4.5:1. The categorical colours (tab groups, toolbar container colours) keep their own hues. The desktop browser is not recoloured yet.
- **Mozilla experiments and rollouts (Nimbus):** removed as a remote control. The app fetched Mozilla's experiment collection on every start and applied 11 bundled experiments and rollouts, whatever the telemetry and studies settings said (details in [network](./network.md)). That is how an unfinished tab groups tab reached the app. Nimbus now gets no Remote Settings service (`Components.kt`) and `initial_experiments.json` is empty, so features follow `nimbus.fml.yaml` only. Tab groups, user surveys, the sports widget and the LongFox game are therefore off. A feature can be turned on on purpose by changing its default in `nimbus.fml.yaml`. After an ESR upgrade take our empty `initial_experiments.json` again and check `Components.kt`; the guard fails otherwise.
- **Link and referrer privacy:** tracking parameters are stripped from links in normal and private tabs (Fenix had this hard-coded off); cross-site referrers are cut to the origin even when a page asks for more, and classified trackers get no referrer. Encrypted Client Hello was checked and is already on. Details and the reasons are in [network](./network.md). The guard checks the two stripping values and the three prefs. Bundling uBlock Origin and Privacy Badger in the app was looked at and not done: the first-run prompt already installs them only after the user taps Install, the installer could take local files, but it would not remove the update checks to Mozilla and adds licence duties (both GPLv3).
- **TLS 1.2 ciphers: AEAD only:** in `geckoview-prefs.js` we turn off 3DES (`deprecated.rsa_des_ede3_sha`), the four static RSA key exchange ciphers (`rsa_aes_128_sha`, `rsa_aes_256_sha`, `rsa_aes_128_gcm_sha256`, `rsa_aes_256_gcm_sha384`) and the three ECDHE CBC ciphers (`ecdhe_rsa_aes_128_sha`, `ecdhe_rsa_aes_256_sha`, `ecdhe_ecdsa_aes_256_sha`). What is left in TLS 1.2 is ECDHE with AES-GCM or ChaCha20, which have forward secrecy and authenticated encryption. TLS 1.2 stays the minimum and TLS 1.3 the maximum, as in Mozilla. This is stricter than Mozilla: a site that only offers CBC fails with a connection error. In build 28 and later (now build 30 (commit `fb02ae860a`)), no connection problems reported so far. To allow such a site again, set the pref it needs back to true; the guard checks all eight prefs, so change `expected-prefs.json` with it.
- **TLS 1.3 early data (0-RTT) off:** `security.tls.enable_0rtt_data` is false in `geckoview-prefs.js`. Early data sent on a resumed connection has no replay protection from TLS, so a network attacker can resend it. Costs one round trip on resumed connections. In build 30 (commit `fb02ae860a`). Set it back to true and change `expected-prefs.json` to undo.
- **Safe renegotiation required:** `security.ssl.require_safe_negotiation` is true in `geckoview-prefs.js`. Mozilla leaves it false so that very old servers still connect. With it on, a server that does not support the secure renegotiation extension (RFC 5746) fails with a connection error instead of being allowed to renegotiate insecurely. It only affects TLS 1.2, since TLS 1.3 has no renegotiation. In build 30 (commit `fb02ae860a`), not tried on many sites. Set it back to false and change `expected-prefs.json` to undo.
- **Only the 2 latest tabs stay active:** new `BackgroundTabsLimitMiddleware.kt` (registered in `Core.kt`). When the selected tab changes, every tab except the selected one and the most recently used other one is suspended: its state is saved, its page is closed, and it is rebuilt from the saved state when opened again. A suspended tab runs no scripts and makes no connections, which is a privacy gain as well as a memory one. Mozilla only does this under memory pressure (`TrimMemoryMiddleware`, which Fenix turns off with `trimMemoryAutomatically = false`) and keeps 3 tabs. Tabs with typed form input and tabs that are still loading are never suspended. Two switches in Settings, Tabs, Background tabs: "Keep only the 2 latest tabs active" (on by default) and "Keep tabs playing media active" (off by default, so a song stops when its tab is not one of the 2 latest). `limitBackgroundTabs` and `keepMediaTabsActive` defaults are checked by `check-fork.py`. In build 30 (commit `fb02ae860a`), which compiled and was installed on a phone. Checked on a phone: tabs reload on return, forms are kept, and media behaves with the switch on and off.
- **Settings that did nothing are gone or hidden:** with telemetry compiled out and Mozilla's experiments and rollouts cut, these only gave the impression of a choice. The Studies screen and the Remote improvements entry are deleted: the `settings/studies` code, `RemoteImprovementsFragment`, their layouts, navigation entries, strings, tests and the `isRolloutsEnabled` setting. The "usage and technical data" and "daily usage" switches on the Data collection screen are deleted too (state, actions, reducer, middleware, settings search entries, strings and tests); that screen holds the crash report choice only. The usage data switch in the first-run "Manage settings" dialog is deleted as well (its state, actions, repository branch, telemetry events in the app code and tests); the dialog has the crash report switch only. The Glean metric definitions for it stay in `metrics.yaml`, unused. The guard fails if any of these come back.
- **LongFox game:** Mozilla's snake-style game and everything around it: the `longfox` module with its sounds, font and Glean metrics, the fox peek animation on the privacy report card, the homepage entry point and its settings, the secret setting, the Nimbus feature and the launch counter. It was off in release builds and could only be switched on by an experiment.
- **Strict tracking protection by default, with fingerprinting protection in every tab:** `useStrictTrackingProtection` now defaults to true and `useStandardTrackingProtection` to false (in `Settings.kt` and `tracking_protection_preferences.xml`). A phone that never chose a level moves to Strict; one that chose Standard or Custom keeps its choice. Fingerprinting protection (`privacy.fingerprintingProtection`) is now applied at every start from the chosen level (Strict: normal and private tabs, Standard: private tabs only, Custom: as set). Upstream only applied it when the Tracking Protection screen was opened or when the `fingerprinting-protection` Nimbus feature was on, so before this a Strict choice did not reach the engine after a restart. Strict blocks more content and can break some sites, which can be allowed one by one from the shield in the toolbar. The `fingerprinting-protection` Nimbus switches that used to control this (`enabled`, `enabled-normal`, `enabled-private`, `overrides`) are removed from `nimbus.fml.yaml`; only `fdlibm-math` is left. `SettingsTest` covers the new defaults and the fingerprinting rules. Compiled in build 31 (commit `3902e41696`); not checked on a phone yet.
- **Homepage sports widget (World Cup):** the widget, its country picker, match cards and promo cards, the `home/sports` and `appstate/sports` code, the debug tool, the "World Cup" switch in Customize home, the secret setting and the mock server settings, the `homepage-sports-widget` Nimbus feature, the `world_cup` Glean metrics, the strings, the wordmark with the sports logo (the homepage logo is always the plain wordmark now) and its tests. It was off in release builds, but it was built to fetch tournament data from Mozilla's servers. Left in place: the Search optimization sports suggestion cards, which are a separate feature (`showSportsCard`, off by default) from android-components. Mozilla's fox pictures that went with it, plus the other visible Mozilla fox art (the default-browser menu banner, the empty Downloads screen, "no results" in tab and settings search, the startup crash screen and the AI controls screen), are replaced by the FragmentedFox fox from `make-android-icons.py`, under the same file names so ESR merges stay small. The 48 country flag pictures the widget used are deleted too. It compiled in build 30 (commit `fb02ae860a`) and the app was installed on a phone. Not specifically checked on a phone: the homepage and menu banner, and the missing World Cup switch in Customize home.
- **Translations of removed strings:** the translated `strings.xml` files in `values-*` no longer hold strings that have no English original (about 9,700 entries, mostly from the sports widget, the onboarding variants and other removed features). They were also hiding two references to a removed string in the device tests, now fixed. The guard (`translations`) fails if a translation without an original appears again; after an ESR upgrade remove those from the new files the same way.
- **Unused resource files:** two layouts (an add-on data permission row and the date and time picker prompt) and five drawables (a leftover `delete_me.xml`, the QR camera focus image, two tab counter drawables and a ripple drawable) that nothing referenced.
- **Ecosia instead of Bing:** `SearchMiddleware` has a new option, `replaceBingWithEcosia`, which `Core.kt` turns on. It removes every Bing engine (`bing`, `bing-*`) from the region list and the additional engines, and puts Ecosia in the place of the first one, as a normal engine. Ecosia comes from Mozilla's list when the region has it and from the bundled `ecosia.xml` when it does not. The option is off by default, so the upstream tests keep their meaning. Someone who had chosen Bing as the search engine falls back to the default (DuckDuckGo). Ecosia's own results still come partly from Bing, so this changes which engine you can pick, not what Ecosia uses behind the scenes. The device tests in `SearchTest.kt` that switch to Bing will not work any more. Not built or checked on a phone yet.
- **No partner codes in search URLs:** search engines are loaded without the partner and attribution parameters Mozilla adds to result pages (`PartnerParams.kt`, applied in `SearchEngineReader.kt` for the remote list and the bundled engines, except engines you add yourself). Config parameters flagged `{partnerCode}` are left out, and a list of known parameters is removed from Google (`client`, `channel`), Bing (`pc`, `form`), DuckDuckGo (`t`), eBay, Amazon, Yandex, Ecosia, Wikipedia (`sourceid`) and about ten others. The home screen Google shortcut no longer swaps in a `client=firefox-b-m&channel=ts` address (`appendSearchAttributionToUrlIfNeeded` and the two URLs are gone). Left as they were on purpose: suggestion and trending URLs, because Google's `client=firefox` there selects the response format and removing it would break suggestions; and the engine list itself, which still comes from Mozilla's Remote Settings. Search results are still requested from the engine with the same search terms, so the engine sees a plain search. The device tests that looked for the codes in the history now look for the engine's address. Not built or checked on a phone yet.
- **Search results telemetry:** Fenix no longer installs the two search telemetry web extensions ("ads" and "cookies") that watched Google, Bing and other results pages, and no longer downloads Mozilla's `search-telemetry-v2` list from Remote Settings for them. They reported through telemetry that is compiled out, so they did work and made a Mozilla request for nothing. Removed from `Core.kt`: the install block, `AdsTelemetryMiddleware`, `adsTelemetry`, `searchTelemetry` and the collection name. Also removed: their fact handlers in `MetricController` and its test, and the `browser.search` Glean metrics (`with_ads`, `ad_clicks`, `in_content`). The classes in android-components `feature-search` stay because Focus, which the build configures but we do not build or ship, still uses them. Not built yet.
- **Unused Nimbus features:** eight features nothing in the app reads are removed from `nimbus.fml.yaml`: the six `nimbus-qa-*` test features, `networking-happy-eyeballs` and `tracking-protection-experimentation`. Remote experiments are off, so they could never be turned on. `gecko-nimbus-validation` stays because a unit test of `NimbusGeckoPrefHandler` reads it from the manifest. The handler itself and the rest of the experiments code are left for a later cleanup. Not built yet.
- **More unused strings:** 36 strings that nothing referenced any more (add-on update checker, strong password prompt, old error page variants, the redesigned terms-of-use onboarding text and others), with their translations. Three that look unused (`microsurvey_survey_printing_title` and the two `nimbus_notification_default_browser_*`) stay because a Nimbus message file points at them.
- **Leftovers of those removals:** a Glean metric nothing recorded any more (the Vivo file check error), four drawables (the review prompt buttons and the old shield states), the Play Store and Android support URL constants and the unused `Config.isRelease` and `isNormalTab` helpers, the instrumentation tests for "Rate on Google Play", and the app dependency on the accelerometer library that only shake detection used. Strings in the translated `values-*` folders are left alone on purpose: they are not packaged (only `en` is) and touching them would conflict with every ESR upgrade.
- **Play Store review prompt:** the rating prompt and its bottom sheet, the "Rate on Google Play" settings item, the `custom-review-prompt` Nimbus features, the metrics and the Google Play review library. It only works for apps installed from Google Play.

The library modules `lib-push-firebase`, `lib-integrity-googleplay`, `concept-llm`, `lib-llm-gemininano`, `lib-llm-mlpa`, `feature-summarize`, `concept-accelerometer`, `lib-accelerometer-sensormanager`, `lib-shake`, `concept-integrity`, `feature-ipprotection`, `feature-containers`, `feature-serviceworker`, `feature-example`, `lib-jexl`, `ui-fonts`, `ui-richtext` and `support-test-appservices` are deleted, with their entries in android-components `.buildconfig.yml`, because no project the build configures depends on them. `lib-crash-sentry` stays in the tree, not compiled into the app: the build does not set `--enable-android-subproject`, so Gradle also configures Focus, and Focus depends on that module. Deleting it would fail the build at configuration time. Building with `--enable-android-subproject=fenix` would stop Gradle configuring Focus and the samples, and would allow deleting `lib-crash-sentry` and a few modules only Focus uses; not tried yet. Mozilla's Socorro crash reporter stays: it only sends a report if the user taps send on the crash screen.

## Checked and left as is

- The "+" new tab button in the top toolbar is off by default (`toolbarSimpleShortcutKey` is `none` in `Settings.kt`). A new tab is still one long press away on the tab counter, and the button can be brought back under Settings, Customize, toolbar shortcut. This only applies to new installs, because Android keeps the value already saved on a phone. `expected-settings.json` guards the default.
- Pocket stories, sponsored stories, the Mozilla Ads Client and the Merino manifest are switched off by default in `nimbus.fml.yaml`. The code stays, so these are defaults that `expected-nimbus.json` guards. See [network](./network.md).
- Android Firefox Suggest (`fx-suggest` in `mobile/android/fenix/app/nimbus.fml.yaml`) defaults to off for release builds and is only on for developer and nightly channels. No remote experiment endpoint is configured, so nothing can turn it on.
- Android search suggestions and trending searches default to on (`Settings.kt`), so typed text is sent to the search engine as it is typed. They stay on by default on purpose, and the user can turn them off in settings.


## Android security review

Checked in the app manifest: backups are off (`allowBackup=false`), the only exported components are the launcher and link entry points, the autofill and custom tabs services, the search widget and a QA receiver protected by the `DUMP` permission. `QUERY_ALL_PACKAGES` is kept because "open in app", sharing and default browser detection need it. Not changed, but worth knowing:

- Cleartext traffic is off. `usesCleartextTraffic` is false and the network security config refuses cleartext except for `localhost` and `127.0.0.1`. This only governs Android's own Java networking, since Gecko does its own networking and HTTPS-Only mode covers pages. The fork guard checks it. If an app feature that fetches over plain HTTP stops working, this is the first place to look.
- `REQUEST_INSTALL_PACKAGES` stays, as Mozilla ships it. Removing it (a `uses-permission-sdk-23` entry with `tools:node="remove"`) was part of the first build that would not install. It was later shown that the aliases alone cause the failure, but the removal was never tested on its own, so leave it alone until it is. The browser can launch the installer for a downloaded APK, but only after the user allows it for FragmentedFox in system settings.
- `QUERY_ALL_PACKAGES` stays. The share sheet, the app icon picker and open-in-app links need it. Dropping it would need a `<queries>` list and testing on a phone.
- `CAMERA` and `RECORD_AUDIO` are declared. WebRTC is compiled out, so sites cannot use them, but the QR scanner and similar features may. Nothing is requested until a feature asks.
- Every pref named in the Desktop section above was checked and still exists. `app.shield.optoutstudies.enabled` is set to false twice in `firefox.js`, harmlessly, because both branches of Mozilla's `#ifdef` now say false.

## Names and branding

- The release build's launcher icon (including the themed monochrome version), the home and shortcut wordmarks and the search widget image are FragmentedFox's. They live in `mobile/android/fenix/app/src/release/res`, which overrides `src/main/res` for release builds, and were added with the Android branding commit. The launcher background colour and the splash screen background are `#050505`.
- The notification status icon and the in-app logo drawables (`ic_firefox`, `expressive_firefox`, `ic_status_logo`, `mozac_ic_logo_firefox_24`) are the FragmentedFox fox. They are generated from `browser/branding/fragmentedfox/source/icon-small.svg` by `python3 .github/scripts/make-android-icons.py`, so rerun it if the logo changes. The same script also writes launcher icon files into `src/main/res`, but release builds use the ones in `src/release/res` instead, so those only matter for other build types.
- `browser/branding/fragmentedfox` and `mobile/android/branding/fragmentedfox` are the default branding directories. SVG sources for the logo are in `browser/branding/fragmentedfox/source`.
- The application vendor is `FragmentedVisions` (desktop and Android) in `browser/moz.configure` and `mobile/android/moz.configure`.
- Network error pages, the names of browser-owned features (View, Home, Labs, Screenshots, Translations, Suggest), the Windows startup dialog title and the distribution text say FragmentedFox.

## Known gaps

- The tracker counts on the privacy report disagree by a small number. The tab tray pill and the "since" footer show the all-time total, which the engine sums over every stored event type (`sumAllTrackingProtectionEvents`). The "this week" card adds up only four categories (cross-site cookies, social, fingerprinters and tracking content), and Mozilla's code leaves out other cookies, cryptominers and bounce trackers on purpose (`TrackersBlockedFeatureTest` covers this). So the pill can read higher than the card (14 against 13 was seen). This is Mozilla's behaviour and is in every build. Left alone to keep the change small; the fix would be to make the total count the same four categories.
- Gradle prints a warning that two Kotlin plugin versions are in use. The version catalog (`gradle/libs.versions.toml`) sets Kotlin 2.3.21, but `mobile/android/gradle/plugins/apilint` and `nimbus-gradle-plugin` pin 2.3.10. This is how Mozilla ships this ESR, it does not fail the build, and it is left as is so it does not differ from Mozilla's code.
- The Capital One sign-in (auth) page shows a blank white page. Another sign-in route on the same site works. It fails on a clean install of build 23 and of build 14, on the desktop site, and on current official Firefox, so it is not caused by anything the fork changed, and cause is unknown. It works in WebLibre, which embeds a community-built GeckoView labelled 158.0.2 (from a GitLab Maven registry, not Mozilla's; Mozilla's tags show 158.0 and 158.0.1) and also uses Quad9. Ruled out: extensions, tracking and fingerprint protection settings, stored data and Nimbus rollouts (clean installs), WebRTC, the user agent, DNS (Quad9 on both), referrer trimming, link parameter stripping and the cleartext flag. Not yet looked at: the page's console and network errors (use Remote debugging via USB with `about:debugging` on desktop Firefox), and differences between WebLibre's engine build or runtime settings and ours. If it gets fixed, record what fixed it here.
- The Data collection screen and the first-run "Manage settings" dialog still show the technical data, daily usage and Studies switches. Turning "technical data" on starts Mozilla's experiments (Nimbus) over Remote Settings, though Glean uploads stay blocked by the build flag. Whether to hide them is undecided.
- uBlock Origin and Privacy Badger overlap in what they block. Running both costs some memory and gives little extra protection, so one may be dropped later.
- The first-run Terms page keeps its structure and buttons (accepting still records acceptance and starts the telemetry client, which stays disabled by the build flags), but its text now describes the licence and links to the README. The privacy line says the app is set up not to send diagnostic data to Mozilla. That statement has not been verified on a running build yet.
- Translations in other languages still say Firefox, and some Android strings, images and links still mention Firefox or Mozilla.
- No update server. The desktop build is configured with the updater off, so new versions are shipped as downloads.
- The default search engines, Sync and add-on sources are Mozilla's.
- `Assets.car` (a compiled macOS asset catalog) still has the old icon.
- Google's `oss-licenses` Gradle plugin was reviewed. In the plugin's source it makes no network requests of its own and sends no telemetry; it only reads dependency metadata that the build has already downloaded, and writes the licence list into the build folder. The app does not include Google's `play-services-oss-licenses` library: the About screen uses Mozilla's own `LibrariesListFragment`, so no Google code runs in the app. Mozilla applies the plugin only when `MOZILLA_OFFICIAL` is set, which our builds do not set, so the licence screen showed Mozilla's placeholder text from `res/raw/third_party_licenses`. `fenix/app/build.gradle` now applies the plugin to every build except lint, and the guard fails if the `MOZILLA_OFFICIAL` condition comes back. It built without a duplicate `third_party_licenses` resource error in build 30 (commit `fb02ae860a`) (the placeholder files are still in `src/main/res/raw`). Not specifically checked on a phone: that Settings, About, Libraries lists real licences. The plugin's classpath entry is still resolved from Google's Maven repository at build time, like the Android Gradle Plugin itself. Version 0.12.0 itself was not read; the review used the current source.
- The network contacts in [network](./network.md) come from reading the code and defaults, not from watching traffic. A capture on a fresh install was tried three times and failed to record the app's traffic (see [building](./building.md)), so it is still to do.
- The fox mascot illustrations that users can see, and the default-browser banner picture, are now the FragmentedFox fox (see the sports widget bullet above). A second pass replaced Mozilla's Kit fox in the Tracking Protection panel (all three states), the Firefox Labs screen, the empty bookmarks screen, the bookmarks folder picture and the two tab group onboarding pictures (the tab group ones keep their colored tiles beside the fox). They are drawn by `make-android-icons.py` under the same file names. `kit_sleeping_under_laptop.webp` became an XML drawable of the same name. The "no internet" error page picture (`mozac_error_no_internet_connection.svg` in `ui-icons` assets, shown for NS_ERROR_OFFLINE) is now the fox with an unplugged cable, drawn by the same script. The other error page pictures are generic emoji-style icons and stay. Compiled in build 31 (commit `3902e41696`); not checked on a phone yet. The rest of the Android artwork has not been checked for other Mozilla art, such as onboarding pictures. The launcher icon and the home and shortcut wordmarks are already FragmentedFox's in release builds.
