# Code health, fixes and tooling

Fixes, dependency and build-tooling changes, and clean-ups that remove dead code without changing behaviour. Which build each is in: see [status](./status.md).

- **Base64 fixes in the app layer:** an audit of every place the app decodes Base64 found four crashes on bad input. `String.base64ToBitmap()` (used for the icons that a website's federated login provider hands to the account picker) now returns null for text that is not valid Base64, as its comment already promised, instead of throwing. Loading custom search engines no longer crashes on a stray file in the engine folder (a leftover `.new` or backup file from an interrupted save) and skips it. A custom search engine whose icon is not valid Base64 loads without the icon. The profiler upload decodes the server's token as URL-safe Base64 (JWTs are, and `Base64.DEFAULT` rejects `-` and `_`) and fails with a clear error when the reply is not a token. A unit test was added for the first. Compiled in build 40 (commit `2c79351500`).
- **GitHub Actions pinned to commit SHAs:** `actions/checkout`, `cache`, `upload-artifact`, `download-artifact`, `create-github-app-token` and `android-emulator-runner` were referenced by tag (`@v7`), and a tag can be moved by whoever controls that repository. The signing key and the release token are available to these jobs, so every `uses:` now names a full commit SHA with the version as a comment, and `check-fork.py` fails on any that does not. Ran in build 41 (commit `9be010b72a`), which passed. They were then moved to newer releases: `checkout` 7.0.1, `cache` 6.1.0, `upload-artifact` 7.0.2, `download-artifact` 8.0.2, `create-github-app-token` 3.4.0 and `android-emulator-runner` 2.38.0. The release notes show no removed inputs for how the workflows use them; `download-artifact` 8 now fails on a hash mismatch and skips unzipping non-zip files, and ours are zips. Not run yet with these versions.
- **Android SDK levels checked, target SDK stays at 36:** the build already compiles against the newest platform (API 37, Android 17) with build tools 37.0.0 (`android-sdk.configure`, `android-components/.config.yml`). `targetSdkVersion` is 36, as in Mozilla's code. Raising it to 37 was tried and backed out: for apps that target 37, Android 17 blocks access to local network addresses unless the app declares and requests the `ACCESS_LOCAL_NETWORK` permission, which would stop pages on a router, NAS or home server from loading until the browser asks for it. Going to 37 needs that permission added and a prompt wired to it first. The guard fails if the two target values differ or move off 36. Not built yet.
- **Unused version catalog entries removed:** seven libraries nothing referenced (`sentry`, `kotlin-annotations-jvm`, `androidx-constraintlayout-compose`, `androidx-datastore-core`, `androidx-compose-runtime-livedata`, `androidx-compose-ui-graphics`, `androidx-test-espresso-web`) and the three version entries only they used, in `gradle/libs.versions.toml`. `jna`, `jacoco` and `ktlint` look unused to a quick search but are read by the native-layer build scripts and Gradle files, so they stay. Not built yet.
- **Unused Glean metric definitions removed:** 24 metrics and 3 whole categories (`privacy_notice_banner`, `private_browsing_shortcut_cfr`, `voice_search`) that no code references are deleted from `metrics.yaml` (432 lines), so Glean no longer generates classes for them. They are the metrics of the Terms of Use prompt, the privacy notice banner and the first-run dialog, plus a few older ones in `onboarding`, `bookmarks_management`, `history`, `start_on_home`, `activation` and `terms_of_use`. A first scan reported 132 and was wrong for most of them: it missed metrics used through import aliases (`GleanHistory`) and inside `with(Metrics)` blocks. The list was cut to what an alias-aware search finds in no file. The `broken_site_report` and `webcompatreporting` metrics with no references were left, because that schema mirrors Mozilla's reporter. Compiled in build 41 (commit `9be010b72a`).
- **Stale lint and detekt baseline entries removed:** 56 entries in `config/detekt-baseline.xml` and 6 in `app/lint-baseline.xml` that named files we deleted (Adjust, microsurveys, the review prompt, IP protection, sports and others) are gone, so the baselines do not hide new warnings in code that moves into those names.
- **Cache hang fix, backported in part (bug 2052908):** Mozilla's ESR 153.6 can leave a cache entry marked "being written" forever, so every later request for the same URL waits for a writer that never finishes. It happens when a cache writer is suspended while the tracking-protection check runs and is then cancelled (an address-bar autocomplete request cancelled as you type is one trigger). Mozilla fixed it in 153.7, but our test of 153.7 (build 38) got stuck pages on the Google Store (tapping Tech specs, then the next search was blank), and the cause was never pinned down. We did not take the 153.7 upgrade. Instead, on 153.6, `netwerk/protocol/http/nsHttpChannel.cpp` and `.h` and `netwerk/cache2/CacheEntry.cpp` carry two small parts of Mozilla's fix: (1) `CancelInternal` now undoes the tracking-protection suspension, using a new flag `mSuspendedForExamineResponse` so the matching `Resume()` happens exactly once, so a cancelled writer closes its entry; (2) in `CacheEntry::InvokeCallback`, a consumer that waits for a write to finish is handed the entry as "not wanted" (so it goes to the network) when the writer-lock bypass is on, instead of waiting forever. We did not take Mozilla's other parts: the 20-second backstop timer (`network.cache.entry_wait_timeout_ms`), the mutex around the cache check and the reset of the cache state on every check (`DiscardCacheEntryCheckState`), which were the likeliest cause of the stuck pages. `check-fork.py` fails if our two changes go missing. When upgrading to an ESR that contains Mozilla's version of this fix, take Mozilla's files for these three and drop ours. Compiled in build 41 (commit `9be010b72a`).

In the app: the unused `webcompat-reporter-enhancements` Nimbus feature, three unread settings with their preference keys, and a few unread constants (`TWO_DAYS_MS`, the remote settings endpoint URLs, `isReleaseOrBeta`, two unused toolbar telemetry names, two trace tags, `SHARE_ALL_TABS`), plus the unused `eagerFlingBehavior` composable. `BrowserMenuSwitch` stays because a customtabs test uses it.

The `androidTest` dependencies in `app/build.gradle` and the exclusion patterns in the lint and detekt configs are left as they are, because they do nothing without that folder. Nine strings that nothing referenced any more (the Pocket and Stories texts and `content_description_normal_browsing`) are removed from every language. - **Translations of removed strings:** the translated `strings.xml` files in `values-*` no longer hold strings that have no English original (about 9,700 entries, mostly from the sports widget, the onboarding variants and other removed features). The guard (`translations`) fails if a translation without an original appears again; after an ESR upgrade remove those from the new files the same way.
- **Unused resource files:** two layouts (an add-on data permission row and the date and time picker prompt) and five drawables (a leftover `delete_me.xml`, the QR camera focus image, two tab counter drawables and a ripple drawable) that nothing referenced.
- **Unused Nimbus features:** eight features nothing in the app reads are removed from `nimbus.fml.yaml`: the six `nimbus-qa-*` test features, `networking-happy-eyeballs` and `tracking-protection-experimentation`. Remote experiments are off, so they could never be turned on. `gecko-nimbus-validation` is removed as well, together with `NimbusGeckoPrefHandler` and `NimbusGeckoUtils` (the `experiments/prefhandling` package, about 700 lines, its README, picture and test). With remote experiments off it only added start-up work, so `createNimbus`, `NimbusComponents` and `FenixApplication` no longer create or call it. Nimbus itself, its generated feature classes and messaging stay. Compiled in build 37.

- **Tracker counts agree:** the all-time total (tab tray pill, home screen, privacy report footer) used to be the engine's sum of every stored event type, while the "this week" card counted only four categories (cross-site cookies, social, fingerprinters including suspicious ones, and tracking content), so the pill could read higher than the card (14 against 13 was seen). `TrackersBlockedFeature.kt` now reads the tracking events from the start of time and sums the same four categories for the total, so the total can no longer be lower or higher than the weekly figure because of a different definition, only because of the time window. Other cookies, cryptominers and bounce trackers are still left out of both, as in Mozilla's weekly card. The old `fetchTotalTrackersBlocked` use case stays in android-components but the app no longer calls it. Not yet built or checked on a phone.
