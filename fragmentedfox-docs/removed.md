# Removed from the Android app

Removing a feature means deleting its code, resources, metrics, tests and dependencies. Which build each removal is in: see [status](./status.md). Do not add these back (see `removed.json`, which `check-fork.py` uses).

- **Google Lens removed:** the toolbar Lens button, the "Search with Google Lens" image menu entry, the Lens camera screen and its camera permission flow, the image uploader and file provider, the Lens state and actions in the app store, the Google Lens switch in the AI controls screen and the debug menu, the `google-lens-integration` Nimbus feature, strings in every language and the tests. It was already off in release builds (the Nimbus flag defaults to off outside developer and nightly), so nothing a user could reach is gone. The address bar QR scanner is a separate feature and is unchanged. The AI controls screen now lists Translations and voice search only. The guard fails if any of it returns. Not built yet.
- **Firefox Labs removed:** the Labs screen, its store, middleware and telemetry, the settings entry (hidden by `FIREFOX_LABS = false`), the debug switch, the settings search entry, the navigation destination, the `firefox_labs` Glean metrics, strings in every language and the tests. With experiments off there was nothing to list in it. Not built yet.
- **First-run "Manage settings" dialog removed:** the dialog titled "Help us make Firefox better" held one switch, automatic crash reports, and crash reporting is compiled out (`BuildConfig.CRASH_REPORTING` is false), so the switch changed nothing while the title implied it helped Mozilla. The dialog, its fragment, store, middleware, repository, telemetry middleware, string resources (in every language), the click event in the telemetry recorder, the `line-three-link-text` Nimbus field and the tests are deleted. The third line of the welcome page ("FragmentedFox is set up not to send diagnostic or interaction data to Mozilla.") is now plain text. The guard fails if the dialog file returns. Compiled in build 41 (commit `9be010b72a`).
- **Terms of Use prompt and privacy notice banner removed:** the Terms of Use bottom sheet (shown after a number of launches to people who had not accepted, only when the Nimbus feature `terms-of-use-prompt` was on, and its default was off), the homepage "privacy notice updated" banner (shown only to people who accepted the terms before 17 December 2025, which cannot be true of a FragmentedFox install), their stores, middlewares, repositories, `TermsOfUseManager`, the bottom sheet fragment and its nav graph entries, the Nimbus feature `terms-of-use-prompt` and its content option enum, eight preferences (prompt enabled, drag handle, displayed count, content option, last prompt time, postponed, the privacy banner timestamp and two debug switches in the secret settings), 17 strings in all languages, and their tests (about 1,700 lines plus tests). Kept: the first-run Terms page and the settings that record acceptance (`hasAcceptedTermsOfService`, accepted date and version, `TOU_VERSION`), and the `termsofuse/experimentation` targeting code, because `RecordedNimbusContext` still reports `touPoints`. Compiled in build 41 (commit `9be010b72a`).
- `nimbus.fml.yaml`: the marketing onboarding card (sharing install data with Mozilla's marketing partners) defaults to off.
- IP Protection (Mozilla VPN) engine code is removed from the Android build: `toolkit/components/ipprotection` is no longer built for Android (`toolkit/components/moz.build`), and `GeckoViewIPProtection.sys.mjs`, its startup registration, `IPProtectionController.java`, `GeckoRuntime.getIPProtectionController()` and the `api.txt` entries are deleted. The files in `toolkit/components/ipprotection` stay on disk so ESR merges stay clean. The `vpn.mozilla.org` endpoint and auth provider prefs are gone; `browser.ipProtection.enabled` stays false. Not yet built.
- **Mozilla VPN (IP Protection):** the settings entry, menu item, toolbar pill, trust panel section, first-run prompt, snackbars, account sign-in hooks, navigation destinations, the `ip-protection` Nimbus feature, the Fenix dependency on `feature-ipprotection`, the strings in every language, the `vpn` Glean metrics and the matching tests. Left in place: the shared android-components and GeckoView VPN code, which nothing in the app uses, and entries for the deleted files in the lint and detekt baselines. `browser.ipProtection.enabled` is also false in `geckoview-prefs.js`.
- **Third-party SDKs:** Adjust marketing attribution, the Google Play install referrer and advertising ID reader (and the Return to AMO handler that used the referrer), Firebase push (so web push and push-based Send Tab alerts are gone, and were already off without a Firebase config), Google Play Integrity, and Sentry crash reporting. Their dependencies, manifest entries, build tokens, debug screens, settings, Glean metrics, the `adjust-attribution` ping and tests are removed.
- **Page summarizer ("shake to summarize"):** the summarize screen and page content extraction, the Summarize menu item and toolbar highlight, the shake detector, the Page summaries settings screen and its AI controls entry, the `shake-to-summarize` Nimbus feature, the metrics, the instrumented tests, and the `feature-summarize`, `lib-llm-mlpa` and `lib-shake` dependencies. It sent page text to a Mozilla-hosted service, so no page text leaves the device for summarising any more.
- **Installed apps probe and partner distribution code:** the startup check that listed which Mozilla apps were installed (it only fed two telemetry metrics), and the distribution manager that detected partner preinstalls (Vivo, Digital Turbine, Aura, Xiaomi). The distribution code queried other apps' content providers on first run, could switch marketing telemetry on without a prompt on partner devices, and needed the `com.adjust.preinstall.READ_PERMISSION` permission, which is gone too. Their metrics, debug screen, setting and tests are removed.
- **Growth tracking and attribution leftovers:** the conversion event system that reported install and usage milestones to Adjust (the event types, the metrics storage and its 14 settings, the one-week worker and the controller track path), the install referrer UTM settings and their fields in the Nimbus targeting context, the Meta, TikTok, Reddit and X attribution flags, and the Play Store attribution ping with its Meta metrics. They were only written by code that is gone, so they were always empty.
- **Marketing data consent:** the first-run onboarding card and its Nimbus config, the "Marketing data" switch in Data choices, the marketing telemetry settings and the marketing service type, with their metrics, strings and images. It was already unreachable. The notification channel named "Marketing" (used by in-app messages) is a different thing and stays.
- **Font list worker:** a background job that read every font on the device to build a `font-list` telemetry ping, with its font file parser, setting, ping definition and tests. Telemetry is off so nothing was uploaded, but the job still ran and read the device's font list.
- **About screen links:** What's new, Support, Privacy notice and Know your rights pointed at Mozilla's release notes, support site and privacy notice. They now open pages in this repository: `changes.md`, the issue tracker, `PRIVACY.md` and `licensing.md` (constants in `SupportUtils.kt`, resolved against the default branch). The links work once those files are on `Stable-Main`. The guard fails if the old references come back. The first-run terms card already pointed at the licence and the README.
- **Mozilla experiments and rollouts (Nimbus):** removed as a remote control. The app fetched Mozilla's experiment collection on every start and applied 11 bundled experiments and rollouts, whatever the telemetry and studies settings said (details in [network](./network.md)). That is how an unfinished tab groups tab reached the app. Nimbus now gets no Remote Settings service (`Components.kt`) and `initial_experiments.json` is empty, so features follow `nimbus.fml.yaml` only. Tab groups, user surveys, the sports widget and the LongFox game are therefore off. A feature can be turned on on purpose by changing its default in `nimbus.fml.yaml`. After an ESR upgrade take our empty `initial_experiments.json` again and check `Components.kt`; the guard fails otherwise.
- **Nimbus messaging and microsurveys removed from Fenix:** the `messaging` package (`MessagingMiddleware`, the messaging state, reducer and actions in `AppStore`, `MessagingFeature`, the message controllers, `FenixMessageSurfaceId`), the homepage message card (`MessageCard`, `NimbusMessageState`), the full-screen survey dialog (`ResearchSurfaceDialogFragment`), the whole `microsurvey` package (the prompt, the bottom sheet and the fragment), the bottom toolbar container that only the microsurvey prompt created (`BottomToolbarContainerView` and `BottomToolbarContainerIntegration`, with the height it added to the browser layout), the `microsurveys` Nimbus feature and the two microsurvey settings, the secret settings switch, and 37 strings (survey, likert scale, default browser card and notification texts, the marketing channel name and the strings only the deleted device tests used) in every language. `MessageNotificationWorker` is gone with its QA receiver: it was not tied to the experiments switch, so it ran whenever notifications were allowed, tried to fetch Nimbus experiments and could show Mozilla's built-in "default browser" notification; it can no longer run. The built-in message file (`messaging-evergreen-messages.fml.yaml`: default browser card and notification, printing survey) is deleted. Kept: `CustomAttributeProvider` and the JEXL helper in `NimbusComponents`, which the experiments setup and onboarding still use. Compiled in build 37 (commit `cbd89e5d79`), which was installed and checked on a phone.
- **Pocket and the Stories feature removed:** the homepage Stories section and the Stories screen (`home/pocket`, `StoriesFragment`), the content recommendation state, actions and reducer in `AppStore`, `PocketMiddleware` and its data store and `.proto` file, the `service-pocket` library module (Pocket and MARS sponsored story clients), the stories toggles and settings in Customize homepage, the `HomeSettings` Pocket preferences, the `private-mode-and-stories-entry-point` experiment (its experimental homepage header, news button settings and secret setting), the `PersistStoryUTMRequestInterceptor` and the back button logic for tabs opened from stories, the `pocket`, `home.content.article` and `stories_library` Glean metrics, the `home` and `spoc` pings and the `PocketIntegration` tag. The `pocket` and `pocket-sponsored-stories` values are gone from the Nimbus `HomeScreenSection` enum. Two experiment flags that the Terms of Use scoring code reads (`showSponsoredStories`, `showStoriesFeature`) now report false. Checked on a phone in build 34: the homepage and Customize home work.
- **Settings that did nothing are gone or hidden:** with telemetry compiled out and Mozilla's experiments and rollouts cut, these only gave the impression of a choice. The Studies screen and the Remote improvements entry are deleted: the `settings/studies` code, `RemoteImprovementsFragment`, their layouts, navigation entries, strings, tests and the `isRolloutsEnabled` setting. The "usage and technical data" and "daily usage" switches on the Data collection screen are deleted too (state, actions, reducer, middleware, settings search entries, strings and tests); that screen holds the crash report choice only. The usage data switch in the first-run "Manage settings" dialog is deleted as well (its state, actions, repository branch, telemetry events in the app code and tests); the dialog has the crash report switch only. The Glean metric definitions for it stay in `metrics.yaml`, unused. The guard fails if any of these come back.
- **LongFox game:** Mozilla's snake-style game and everything around it: the `longfox` module with its sounds, font and Glean metrics, the fox peek animation on the privacy report card, the homepage entry point and its settings, the secret setting, the Nimbus feature and the launch counter. It was off in release builds and could only be switched on by an experiment.
- **Homepage sports widget (World Cup):** the widget, its country picker, match cards and promo cards, the `home/sports` and `appstate/sports` code, the debug tool, the "World Cup" switch in Customize home, the secret setting and the mock server settings, the `homepage-sports-widget` Nimbus feature, the `world_cup` Glean metrics, the strings, the wordmark with the sports logo (the homepage logo is always the plain wordmark now) and its tests. It was off in release builds, but it was built to fetch tournament data from Mozilla's servers. Left in place: the Search optimization sports suggestion cards, which are a separate feature (`showSportsCard`, off by default) from android-components. Mozilla's fox pictures that went with it, plus the other visible Mozilla fox art (the default-browser menu banner, the empty Downloads screen, "no results" in tab and settings search, the startup crash screen and the AI controls screen), are replaced by the FragmentedFox fox from `make-android-icons.py`, under the same file names so ESR merges stay small. The 48 country flag pictures the widget used are deleted too. It compiled in build 30 (commit `fb02ae860a`) and the app was installed on a phone. Not specifically checked on a phone: the homepage and menu banner, and the missing World Cup switch in Customize home.
- **Play Store review prompt:** the rating prompt and its bottom sheet, the "Rate on Google Play" settings item, the `custom-review-prompt` Nimbus features, the metrics and the Google Play review library. It only works for apps installed from Google Play.


The library modules `lib-push-firebase`, `lib-integrity-googleplay`, `concept-llm`, `lib-llm-gemininano`, `lib-llm-mlpa`, `feature-summarize`, `concept-accelerometer`, `lib-accelerometer-sensormanager`, `lib-shake`, `concept-integrity`, `feature-ipprotection`, `feature-containers`, `feature-serviceworker`, `feature-example`, `lib-jexl`, `ui-fonts`, `ui-richtext` and `support-test-appservices` are deleted, with their entries in android-components `.buildconfig.yml`, because no project the build configures depends on them. Mozilla's Socorro crash reporter stays: it only sends a report if the user taps send on the crash screen.

**Focus is deleted.** `mobile/android/focus-android`, Mozilla's separate Firefox Focus app (about 38,000 lines of Kotlin), is removed. We never built or shipped it, but Mozilla's Gradle settings configured it on every build. The Android build now sets `--enable-android-subproject=fenix` in its mozconfig, so Gradle configures only Fenix and GeckoView. The modules only Focus needed (`lib-auth`, `lib-crash-sentry`) are deleted, and so are the search telemetry classes in `feature-search` that were kept for Focus: the `telemetry` package, `AdsTelemetryMiddleware`, the two extension folders, `search_telemetry_v2.json` and their tests, plus the `updateAdsExtensionVersion` and `updateCookiesExtensionVersion` tasks in that module's `build.gradle`. The upgrade script treats `mobile/android/focus-android` as ours, so an ESR upgrade does not bring Mozilla's copy back, and the guard fails if the folder or the mozconfig flag returns. The android-components `samples` folder (the sample apps) and the modules only they used (`browser-engine-system`, `compose-engine`, `compose-tabstray`, `feature-screendetection`) are deleted too, along with the matching lines in android-components `build.gradle`. `geckoview_example` and `test_runner` are Mozilla's GeckoView test apps outside the folders we own, so they stay in the tree but are not configured. Compiled in build 37.
- **Unused first-run onboarding cards and continuous onboarding:** the Sync sign-in, notification permission, search widget and toolbar placement cards of the first-run flow (they were already switched off in `onboarding.fml.yaml`), the toolbar placement page, the whole `onboarding/store` package (it only held the toolbar choice), and `onboarding/continuous` (the nightly-only flow that spread those prompts over seven days, with its settings, preference keys and the calls in `HomeFragment` and `BrowserFragment`). Gone with them: the 12 onboarding pictures and previews (including Mozilla's artwork for those cards), 13 strings in all languages, 11 Glean metrics (`sign_in_card`, `toolbar_placement_card`, `skip_add_search_widget` and the like), the matching telemetry recorder methods, the FML card types and `ToolbarType`, and their tests. First run is now two cards, the welcome card and the default-browser card. The sync sign-in screen in Settings, the search widget prompt used elsewhere and the setup checklist code are untouched. Not yet built.
